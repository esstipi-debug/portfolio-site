Case Study — Audit Evidence

Turning Inventory Analytics into Audit-Defensible Evidence

Why I researched PCAOB and AICPA standards before writing a line of code — and what a machine-verified, re-performable audit workpaper actually requires.

Problem

Much inventory audit evidence still gets prepared by hand in Excel — a sample size picked "by feel," no re-performable record of which items were tested or why. A regulatory change makes that riskier: the PCAOB has amended AS 1215 to cut the window for assembling final audit documentation from 45 days to 14, and lists the amended standard as effective from 15 December 2026 — whatever gets prepared has to be final-form fast.

Method

Before designing anything, I researched the actual standards: AU-C 530 / AS 2315 (audit sampling), AS 1105 (evidence sufficiency and reliability), and AS 1215 (documentation and re-performability). The key finding: neither standard mandates a specific statistical table — what's mandated is representative sample design, projection of misstatements to the population, and investigation of every exception found. The specific AICPA table values are customary, not required, which is exactly why an engine should implement them precisely and cite them by table number rather than approximate them. The evidence/lineage design reuses Kern's existing writeback-safety pattern (hash-verified, timestamped records) as its closest precedent — the same shape, applied to a read/analysis path instead of a system-of-record mutation.

What I built

src/audit_evidence.py: closed-form attribute sampling (binomial, for tests of controls) and Monetary Unit Sampling (Poisson-gamma reliability factors, for substantive testing of account balances), a GL/trial-balance tie-out with reconciling-item classification, and an evidence record — SHA-256 input hashing, the exact parameters used, a formula-version identifier, and a positive QA attestation — so an independent reviewer can re-derive every number on the workpaper, not just trust it.

Result

30Automated tests, each pinned against a published reference number
3.00MUS zero-error reliability factor at 5% risk — matches the standard AICPA table value
29 / 59Attribute sample sizes at 95% confidence, 10%/5% tolerable deviation rate — classic textbook values, reproduced in closed form
Never executedEvery result ends in a handoff or an escalation — the engine prepares evidence, the auditor of record still concludes and signs

Status: the engine core above is built and tested. Wiring it into the same agent pipeline as the other tools — so it runs end to end like the rest of Kern — is in progress. Full status, file by file: an open pull request in the private repository.
